С 1.5.0 главная — большие карточки питомцев (`petFeedCard`): «питомцы главнее дел», общего списка дел на главной нет — тоже решение владельца. - Есть мобильное приложение того же владельца, «Чистый счёт» (Expo, EAS) — `C:\Users\user\Desktop\Files\clean-count`. Нативная версия Хвостика, если до неё дойдёт, логично делать на том же стеке.

## Принятые решения

1. Статический сайт без сборки и фреймворков: `public/index.html`, `styles.css`, `app.js`. Не добавляй сборщик и зависимости без запроса.
2. Данные в localStorage (`hvostik:data:v1`), ключ журнала и очередь изменений в `hvostik:sync:v1`. Старый ключ темы `hvostik:theme` стирается при запуске. Любые данные из хранилища, файла копии или с сервера проходят через `CLEAN`/`normalize()`.
8. Входа нет — по решению владельца. Доступ к журналу = ключ устройства (в базе только SHA-256). Второй владелец подключается по одноразовому приглашению (7 дней) или ключу восстановления. Не добавляй почту, телефон и аккаунты без решения владельца: это ещё и вопрос 152-ФЗ (база Cloudflare за рубежом).
9. Синхронизация: у каждой записи `ts`; изменения устройства копятся в `meta.pending` и уходят в `/api/sync` пачками до 200; сервер выдаёт номера изменений `rev` в одной транзакции (D1 batch), клиент хранит `cursor`. При конфликте побеждает больший `ts`. Любая правка данных в app.js должна идти через `touch()`/`tombstone()`, иначе она не уйдёт на сервер.
10. Пример (Рекс и Мурка) на сервер не отправляется; свой первый питомец заменяет пример.
11. При ответе 401 (устройство отключили или журнал удалили) локальные записи стираются — это защита на случай потерянного телефона.
12. Фото питомца — поле `photo` у питомца: квадрат 320×320, JPEG, data:-ссылка до 70 000 символов (обычно 20–45 КБ). После выбора файла открывается окно «Выберите область» (`openCrop`: перетаскивание, два пальца, ползунок, колёсико); снимок сначала уменьшается (`loadPhotoSource`), затем выбранный квадрат сжимается (`makePhoto`). У существующего питомца новое фото и «Убрать» сохраняются сразу (`setPhoto`), без кнопки «Сохранить» — раньше люди уходили с формы и фото терялось; у нового питомца фото сохраняется вместе с ним. Фото проверяется `okPhoto` и синхронизируется вместе с питомцем; сервер пропускает питомца до 80 000 символов (`MAX_PET_DATA`), остальные записи — до 4000. Пачка синхронизации ограничена ещё и размером (~700 КБ), чтобы не упереться в лимит запроса 1 МБ. Отдельного хранилища файлов нет — это сознательно, чтобы не усложнять.
13. Виды записей — справочник `TYPES` в app.js (treatment, vaccine, visit, groom); новый вид добавляется туда, `CLEAN.record` пропускает только виды из него. У записи есть `cost` (рубли, 0 — не указано), у питомца — `chip`, `sterile` (yes/no/пусто), `allergy`. Сервер хранит записи как есть, его менять не нужно. Устройство со старой версией сайта не покажет новые виды и, если изменит питомца, сотрёт у него новые поля — поэтому при изменении формата данных всегда поднимай `CACHE`.
14. Скан заключения (с 1.8.0) — вариант «Б», выбран владельцем: распознавание только в браузере, Tesseract.js 5.1.1 + core + русский словарь best_int лежат в `public/ocr` и грузятся при первом скане (~7 МБ), это единственная сторонняя программа в проекте. Фото не хранится и не уходит на сервер. `parseReport` выбрасывает строки с данными владельца и врача (`OWNER_LINE`, `PHONE`) и раскладывает текст по заголовкам (`SECTIONS`; `` с кириллицей не работает — используем `(?![а-яё])`). У визита поля `concl`, `meds` (до 1500), `nextDate` — дата повторного приёма; напоминание у визитов задаёт последний визит питомца. С 1.8.1 перед распознаванием пользователь выделяет рамкой нужную часть листа (`initDocCrop`, можно повернуть), снимок обрабатывается (`prepareDoc`: серый, деление на размытый фон убирает тени, мелкий текст увеличивается); `FIO` убирает ФИО без подписи, `junk` — мусорные строки; если разделы не нашлись, текст не кладётся в «Заключение», а показывается для копирования. Не добавляй распознавание через внешние сервисы без решения владельца.
15. Курс лекарств (с 1.9.0) — запись вида `course`: `days` (1–120), `perDay` (1–6), `marks` ({дата: сколько приёмов}), `stopped` (дата досрочного окончания), чистка в `cleanCourse`. Активный курс (`courseInfo`) делает карточку зелёной «Идёт лечение». Отметки двух членов семьи в один день: побеждает более позднее изменение записи (как везде).
16. Интервал напоминания (с 1.9.1): готовые 1/3/6/12 месяцев, «Своё» (число + дни/недели/месяцы) или «Не надо». Месяцы хранятся в `months`, дни и недели — в `repDays` (дни); везде используй `hasRep`/`nextByRep`/`everyRec`. Окно снизу закрывается смахиванием (`enableSheetSwipe`), при перерисовке сохраняет прокрутку (`renderSheet`); экраны въезжают по глубине (`DEPTH`), разделы карточки проявляются (`seg-body`), при их переключении прокрутка страницы сохраняется (случай `seg`). Выбранное отмечается заливкой или галочкой — чёрных обводок не делаем (решение владельца).
3. Всё, что пользователь ввёл, выводится только через `esc()`.
4. Сроки не назначаются приложением: интервал выбирает хозяин. Это сознательно — чтобы не давать медицинских советов. Не добавляй «рекомендуемые схемы вакцинации» без решения владельца.
5. «Завтра» хранит дату переноса в поле `snooze` последней записи процедуры; перенос не может сделать срок раньше планового.
6. Раздела «Питомцы» нет с 1.5.1 (питомцы на главной), старый `#/pets` ведёт на главную. Маршруты в hash: `#/`, `#/pets/new`, `#/pet/<id>`, `#/pet/<id>/edit`, `#/settings`.
7. Публикация — Cloudflare Workers со статическими файлами (`wrangler.toml`, папка `public`). Адрес: https://hvostik.daniil-projects.workers.dev. Cloudflare перенаправляет `/index.html` на `/`, поэтому офлайн-кэш хранит `/` и не сохраняет ответы с перенаправлением (иначе Safari не откроет сайт без сети).

## Перед тем как сказать «готово»

- Запусти локально (`npx wrangler d1 migrations apply hvostik --local`, `npm run dev`) и пройди: пример → «Завтра» → «Готово» → карточка питомца → новая запись (вес, прививка) → новый питомец → удаление записи → настройки, тема, копия.
- Если трогал синхронизацию или сервер: проверь на двух независимых браузерах (разные профили) — приглашение, общие отметки в обе стороны, работа без сети, отключение устройства, ключ восстановления.
- Для ручной проверки с компьютера есть страница-эмуляция iPhone `public/iphone.html` (адрес /iphone): рамка телефона, внутри сайт в iframe. Отступы под строку состояния и полоску рисует сама рамка, потому что внутри iframe safe-area равна нулю.
- Приоритет — телефоны. Проверь размеры 320×568 (iPhone SE), 375×667, 390–430 по ширине, 360×640/780 (Android) и телефон боком 844×390: нет прокрутки вбок, текст не обрезан, кнопки не меньше 38 px, низ не уходит под меню. Компьютер (≥ 900 px) — во вторую очередь. На узких (≤ 360 px) карточки главной компактнее, при наступлении полуночи «сегодня» пересчитывается без перерисовки открытой формы (`safeRender`).
- Тема только светлая: проверь, что при тёмной теме в системе сайт остаётся светлым.
- Если менялись файлы в `public/`, подними версию `CACHE` в `public/sw.js`.
